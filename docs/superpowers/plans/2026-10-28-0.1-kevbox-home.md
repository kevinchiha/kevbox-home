# 0.1-kevbox-home Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `subagent-driven-development`. This plan
> states contracts, behaviour and constraints — **it deliberately contains no implementation or
> test bodies**. Read the file you are modifying before writing anything; the plan tells you what
> must be true, the codebase tells you how to say it.

**Goal:** Reshape the Couch fork into KevBox Home: one launcher that installs as `tv.kevbox.home`,
shows Kevin's three apps up front with status lines, keeps the rest in a drawer, maps the remote's
app buttons, loads its setup from one pushed file, and updates from tv.kevbox.dev.

**Architecture:** Couch stays one Gradle module of Kotlin on framework Views. Removed features are
deleted outright; everything new lives under `cloud.samlo.couch.kevbox` (config schema, key map,
provisioning, drawer, hold-OK menu, top buttons, status line, restart), and existing Couch files only
gain short hook calls into it, listed in `UPSTREAM-SYNC.md` so `upstream/main` merges stay readable.
Index is the only layout; the accessibility service grows a key filter and a Force-stop runner.

**Tech stack:** Kotlin, Android framework Views (no AndroidX, no Compose), AGP 9.2.1, Gradle 9.8.1,
JUnit 4 plus `org.json` for JVM tests, POSIX shell for the provisioning script.

**Spec:** `docs/superpowers/specs/2026-10-28-0.1-kevbox-home-design.md` (AC-1 to AC-39). UI
reference: `docs/superpowers/specs/assets/0.1-kevbox-home-home.jpg`.

**Foundation chain and lanes.** Tasks 1 to 4 are the foundation and run one after another on the
base branch: 1 removes features, 2 makes Index the only layout and trims Customize, 3 sets identity,
build, copy, manifest and accessibility XML, 4 lays down the config schema, the key map, the
column/drawer list rules, every stub other tasks bind to, and the hook calls in `HomeScreen`,
`HomeLoader` and `IndexScreen`. After task 4 the rest run as parallel lanes, no file in two lanes:

- Lane A: task 5 then task 6 (home column: status line, then layout, More apps, backdrop, focus, Move)
- Lane B: task 7 (top-right buttons)
- Lane C: task 8 then task 9 (drawer, then hold-OK menu)
- Lane D: task 10 (remote keys, Home takeover, Restart app)
- Lane E: task 11 (provisioning)
- Lane F: task 12 (updates)
- Closing: task 13 runs after every lane has merged (docs, `UPSTREAM-SYNC.md`, `AGENTS.md`, gate).

Two cross-lane needs are met in task 4 rather than by a lane editing another lane's file: `Config.FILE`
becomes public for task 10's key cache, and `DrawerActivity`'s companion carries a `takeClosedByBack()`
flag that task 8 sets and task 6 reads, so Back from a drawer opened by a key still lands on More apps.

## Global constraints

- Gate command, run from the repo root: `./gradlew --no-daemon testReleaseUnitTest lintRelease assembleRelease`. It must pass with zero lint errors.
- Release APK size: `stat -c %s app/build/outputs/apk/release/app-release.apk` must print 1048576 or less (AC-35).
- New Kotlin code goes under `app/src/main/java/cloud/samlo/couch/kevbox/` and its tests under `app/src/test/java/cloud/samlo/couch/kevbox/` (AC-2). Existing Couch files get the smallest edit that hooks into `kevbox/`; never move Couch code into `kevbox/` or `kevbox/` code into Couch packages.
- The Kotlin package and the Gradle `namespace` stay `cloud.samlo.couch`; only `applicationId` changes. The four root classes (`MainActivity`, `HomeAccessibilityService`, `MediaListener`, `BootReceiver`) keep their names and package.
- English only. New user-facing text goes in `app/src/main/res/values/strings.xml`, never inline in Kotlin. Do not edit `app/src/main/res/values-fr/` (AC-38 keeps it untouched).
- No AndroidX, no Compose, no new Gradle dependencies, no new Gradle modules. `testImplementation` stays `junit:junit:4.13.2` and `org.json:json:20240303`.
- Follow Couch's file and comment style: one job per file, KDoc comments that say why, no file much past ~160 lines (split a growing file into a second one in the same package rather than letting it run long). Colours, sizes and timings come from `ui/Tokens.kt` and `index/IndexTokens.kt`, never literals scattered in views; text uses `ui/Fonts.kt` (Hanken Grotesk).
- Config keys in `config.json` are a user-facing contract: never rename an existing key. New keys are exactly the ones task 4 declares.
- Edit only the files on your task's **Files** list. After task 4 the lanes run in parallel and no file belongs to two lanes; if a change seems to need a file outside your list, stop and report it instead of editing it.
- The provision file and `config.json` live in `context.getExternalFilesDir(null)` (`UserFiles(context).dir`), which resolves to `/sdcard/Android/data/tv.kevbox.home/files/` for release and `/sdcard/Android/data/tv.kevbox.home.dev/files/` for debug.
- Log tag for every KevBox log line: `KevBoxHome` (constant `KevBox.TAG`, task 4).
- No test reads a source file as text to check what it contains (an import, a prop, a string); test behaviour through the code's own outputs.
- JVM tests cannot call Android framework methods (the test `android.jar` is stubs that throw). Keep testable logic in pure Kotlin functions that take plain values (ints, strings, `File`, `JSONObject`) and return plain values; inject loggers and string lookups as parameters.
- Each task's **Verify** runs only that task's own JVM tests plus compilation, in this form: `./gradlew --no-daemon :app:testDebugUnitTest --tests '<fully.qualified.TestClass>' :app:compileDebugKotlin`. A task with no tests runs `./gradlew --no-daemon :app:compileDebugKotlin`. The reviewer runs the full gate.
- Read every file on a task's **Design skills** line before writing any code for it. Couch's design system (`ui/Tokens.kt`, `index/IndexTokens.kt`, Hanken Grotesk, `Card`, `CardRing`, the expo-out `Tokens.ease`) wins over any skill default. The look to match is `docs/superpowers/specs/assets/0.1-kevbox-home-home.jpg`.
- No screenshot, emulator or visual-check step in any task; Kevin checks screens on a real TV with `docs/kevbox/test-on-tv.md`.
- Commit messages are `type(scope): message` in plain English (for example `feat(drawer): grid of every other TV app`). No AI attribution, no `Co-Authored-By` trailer, no "Generated with" line.
- Never create a `CLAUDE.md` anywhere in the repo; agent instructions go in the root `AGENTS.md` (task 13).
- Forbidden in every task: `git push` of any kind, `adb` or any install on a TV or device, uploads to tv.kevbox.dev or any server, edits outside `/home/kevin/projects/kevbox-home`. The provisioning script is written and shell-checked, never run against a device.
- Safety gate for every agent and every prompt it writes: writing a change is fine; applying it to anything shared, live or irreversible (production data, `git push`, deploys, releases, uploads, `git reset --hard`, `git clean -fd`, force-deleting branches, `rm -rf` of anything this run did not create, printing or committing secrets) needs Kevin's explicit approval of that act first. Stop, state the act and the ways forward, and wait.

**Behaviour:**
