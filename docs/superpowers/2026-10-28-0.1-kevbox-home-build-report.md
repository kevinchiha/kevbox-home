## Lane design (staged build)

Tasks 1–4 form a foundation chain every lane imports (config schema, stubs, manifest, strings), so the
build runs in steps, each merged into `phase/0.1-kevbox-home` and gated before the next. Worktrees are
cut from `phase/0.1-kevbox-home`, not `main`, under `/home/kevin/projects/.worktrees-kevbox-home/`.

1. **Step 1 — foundation**, one lane: `lane-1` = tasks 1 → 2 → 3 → 4.
2. **Step 2 — six lanes in parallel**, after step 1 merges:
   `lane-2` (A) = tasks 5 → 6 · `lane-3` (B) = task 7 · `lane-4` (C) = tasks 8 → 9 ·
   `lane-5` (D) = task 10 · `lane-6` (E) = task 11 · `lane-7` (F) = task 12.
3. **Step 3 — task 13** (docs, sync list, checklist, gate), plain sub-agent on the merged branch.

Longest path is 4 (foundation) + 2 (lane A) + 1 = 7 tasks of 13, so roughly 1.9× faster than one
task at a time, not 13×.
