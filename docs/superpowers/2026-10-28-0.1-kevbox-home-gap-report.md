# 0.1-kevbox-home gap report

The hunt ran four slices (foundation, home, apps, delivery) with 29 agents. All four hunters
returned. 23 raw gaps came down to 21 after removing duplicates. Refuters confirmed 16 and refuted
5. None were disputed or left unverified.

Spec: `docs/superpowers/specs/2026-10-28-0.1-kevbox-home-design.md`
Plan: `docs/superpowers/plans/2026-10-28-0.1-kevbox-home.md`

## Confirmed

### foundation-1 (critical)

**Claim.** After task 1 the gate can never pass. Task 1 deletes strings from `values/` while
`values-fr` keeps them. Lint flags that as `ExtraTranslation`, which is fatal, so `lintRelease`
fails, and so does `assembleRelease` through `lintVitalRelease`. No task adds a lint override, and
task 3's `localeFilters` does not suppress this check.

**Evidence.** `values/` and `values-fr/` hold the same 484 string names today. Tasks 1 and 2 delete
from `values/` only, and a global constraint forbids editing `values-fr`. lint-checks 32.4.0 creates
`ExtraTranslation` with `Severity.FATAL`, and its extra-translation path never calls
`filterLocalesByResConfigs`. `app/build.gradle.kts` has no `lint {}` block and there is no
`lint.xml`.

**Refuters (two, both upheld it at critical).** Each part checks out. The locale filter only feeds
the missing-translation path. The failure shows at task 1's review, since every reviewer runs the
full gate. The reviewer cannot fix it within the rules: `values-fr` is frozen and
`build.gradle.kts` belonged to task 3. The fix is small, but the plan as written cannot reach its
own gate.

**Folded into** Task 1: `app/build.gradle.kts` added to Files, a verbatim
`lint { disable += setOf("ExtraTranslation", "MissingTranslation") }` block inside `android { }`
with its reason, and behaviour 9. Task 3's `values-fr` constraint now points at that block. Spec
AC-38 says the two translation checks are off and why.

### foundation-2 (important)

**Claim.** AC-38 fails on a French TV. `Formats` takes weekday names and the chart's day letters from
`Locale.getDefault()`, and `localeFilters` does not change that. Task 5's status line would read
"Opened mercredi at 22:37".

**Evidence.** `Formats.kt:74-81` builds `SimpleDateFormat("EEEE", current)` and `("EEEEE", current)`
from `Locale.getDefault()`; line 56 even cites "mercredi". Task 3's only AC-38 step is
`localeFilters`. Task 5 routes the status line through `Formats.lastOpened`.

**Refuter.** Upheld. A resource filter picks which `strings.xml` folders ship. It does not touch the
JVM default locale `SimpleDateFormat` reads. Task 13's French AC-38 check would fail on the main
screen. Important: a stated criterion breaks on a common setup, with no crash or data loss.

**Folded into** Task 3: `index/Formats.kt` and `index/SystemLine.kt` (its `rate`, which formats the
bottom line's numbers with `Locale.getDefault()`) added to Files, behaviour 7 pins
`Locale.ENGLISH`, and a constraint names the non-display uses left alone (the weather geocoder's
`language` parameter, `AppSource`'s collator) and `ui/Views.kt`'s `showLongDate`, which only the
unreachable Rows top bar calls. No lane task lists either file. Spec AC-38 now says dates, weekday
names, the chart's day letters and the bottom line's numbers are English too.

### foundation-3 (important)

**Claim.** Task 4's drawer manifest comment says the drawer "joins Home's task and Back lands on
Home". That is false once KevBox Home is the real Home. A drawer opened from another app by a key
starts in its own task, so Back returns to that app, not to More apps (AC-21), and Home does not
clear it.

**Evidence.** `MainActivity` has the HOME filter and provisioning runs `set-home-activity`, so it
runs as a home-type activity. The drawer has no `taskAffinity` and is started with
`FLAG_ACTIVITY_NEW_TASK`. Android's task matching skips a task whose activity type differs, so a
standard activity never joins the home task.

**Refuter.** Upheld. From More apps it works anyway: the drawer's task sits above Home. From another
app it sits above that app, so Back goes there, and the leftover `closedByBack` flag later moves
focus at a random moment. "Home clears it (MainActivity is singleTask)" is wrong too.

**Folded into** Task 4, together with apps-3, as one contract: `KevBox.goHome(context, openDrawer)`
and `KevBox.EXTRA_OPEN_DRAWER` in Produces, behaviour 12, two constraints, `MainActivity.kt` in
Files. Home now opens the drawer itself for keys from other apps. The manifest comment states the
real mechanism. Task 8 behaviours 6 and 7 corrected. Task 10 Consumes and behaviour 5 use `goHome`
for `home` and `drawer`. Spec AC-22 says the drawer opens over Home and Back lands on More apps.

### foundation-4 (important)

**Claim.** Task 4 behaviour 12, the in-Home ALL_APPS fallback for AC-22, never runs. On Android 9
and later the window manager consumes `KEYCODE_ALL_APPS` before any app sees it and opens the
system launcher's app list.

**Evidence.** API 28 added `KEYCODE_ALL_APPS` together with
`PhoneWindowManager.interceptKeyBeforeDispatching` handling it. On leanback that resolves to the
system HOME package, so the key never reaches `MainActivity.dispatchKeyEvent`. Only the
accessibility key filter sees it.

**Refuter.** Upheld at important. minSdk is 28, so this covers every supported box. Task 10 still
delivers AC-22 with the service on. The task 13 link in the claim could not be confirmed (task 13
only switched Projectivy off).

**Folded into** Task 4: behaviour 12 replaced (now `goHome`), Delivers no longer claims a fallback,
and a constraint says why `consumesKey` has no ALL_APPS case. Task 8 behaviour 8 no longer claims
the drawer receives the key. Spec AC-22 says both routes need KevBox Home's accessibility service.
Task 13 behaviour 10 marks the ALL_APPS check "service on". Task 4 had no test intent for the
fallback, so none was removed.

### home-1 (important)

**Claim.** KevBox TV, KevBox Live and SmartTube can lose their channel row, status line and
backdrop art. `Programs.channels` sorts by `pinnedApps` then package name and keeps 12
(`MAX_CHANNELS`). KevBox Home never sets `pinnedApps`, so `tv.kevbox*` sorts after every `com.*`
package.

**Evidence.** `Programs.kt:18` `MAX_CHANNELS = 12`, `:40` order from `pinnedApps`, `:52` the sort,
`:63` `.take(MAX_CHANNELS)`. `IndexData.kt:52` consumes it. No task lists `Programs.kt`.

**Refuter.** Upheld at important. Only the Rows `Organizer` wrote `pinnedApps`, and task 2 makes it
unreachable. It needs 12 busy channels from apps that sort earlier, which grows likelier as members
install streaming apps. It quietly removes the main feature for the three apps the product exists
for.

**Folded into** Task 5 (no other task listed `Programs.kt`): Files, behaviour 12 (`apps` channels
first, in `apps` order, and outside the cap), and a constraint with the reason. Task 5 already had
5 test intents, so no test was added.

### apps-3 (important)

**Claim.** `KeyMap.HOME` reused `openCouch`'s explicit-component start. Once KevBox Home is the real
Home, an explicit start is a standard-type launch that does not reuse the home-type MainActivity,
so Home from an app creates a second MainActivity and HomeScreen.

**Evidence.** Plan task 10 behaviour 5. `HomeAccessibilityService.kt:43-45` `openCouch` has no
category. It only ran while the stock home was in front. AOSP marks a launch HOME only for
ACTION_MAIN + CATEGORY_HOME without an explicit component.

**Refuter.** Upheld at important. The duplicate is capped at one, and the member still sees a KevBox
Home, but a hidden second Home doubles loaders, watchers and bitmaps on a 1-2 GB box.
`ACTION_MAIN` + `CATEGORY_HOME` + `setPackage(packageName)` fits the AOSP rules.

**Folded into** the same `KevBox.goHome` contract as foundation-3 (Task 4 Produces, behaviour 12
and a constraint; Task 10 Consumes and behaviour 5).

### delivery-1 (important)

**Claim.** Task 11 behaviour 5 relied on `Config.save` throwing when `config.json` cannot be
written. The real `Config.save` drops `renameTo`'s result. On FUSE storage that refuses the rename,
`Provisioner` reports `APPLIED` with `config.json` unchanged.

**Evidence.** `Config.kt:81-86` ignores the rename's result. Task 11's own constraint describes
FUSE refusing `renameTo`. `provision.sh` does not check the applied file.

**Refuter.** Upheld at important. `Peers.kt` in the same codebase already handles a failed rename,
so the authors know it happens. A box where the rename fails would break every settings save too,
but provisioning would still claim success.

**Folded into** Task 11 without touching `Config.kt`: behaviour 5 rewritten (reload, compare the
decoded fields, on mismatch keep `kevbox-home.json`, log under `KevBoxHome`, return `FAILED`),
behaviour 2 points at the check, and a constraint keeps `Config.kt` out. `FAILED` added to
`Provisioner.Outcome` in both Task 4's stub and Task 11's Produces.

### delivery-2 (important)

**Claim.** The on-TV checklist only switches Projectivy's accessibility service off, and only on the
TCL. Kevin's boxes also run tvQuickActions, which maps the same buttons, and `provision.sh` keeps
every service already listed. So the key checks fail, or pass for the wrong reason.

**Evidence.** Plan task 13 behaviour 8, spec AC-36, spec AC-8 "keeping every service already
listed". `tellytv-script.sh` and `tvquickactions.sh` enable both services on today's boxes.

**Refuter.** Upheld at important. Netflix opening KevBox TV would look like a pass for AC-28 even
with KevBox Home's filter doing nothing. It could not prove which services are on right now on
Kevin's two devices.

**Folded into** Task 13 behaviour 8 (both devices, before any key or Home check, both packages, the
exact `settings get` / `settings put` lines) and spec AC-36.

## Refuted

### home-5 (claimed important)

**Claim.** Move in the left column can be undone or overwrite newer settings: a reload whose load
ran before placement lands after Move ends and rebinds the old order, and a later save by
`CardMenus` makes the loss permanent. Placement can also write pre-provision values back.

**Refuter.** The timing exists, but the window is a few hundred milliseconds at the end of a Move
that lasts seconds. The file on disk keeps the new order and the next reload shows it. The cited
path to a permanent loss does not exist: `CardMenus` writes nothing for program cards, and task 9
forbids Rename and Hide. The provision case needs a member mid-Move while Kevin provisions the box.
At most minor.

### foundation-6 (claimed minor)

**Claim.** Task 2 breaks `ConfigTest.roundTripKeepsEveryField`, which round-trips
`layout = "rows"`, and never says to rewrite it.

**Refuter.** True but not a gap. Task 2 lists `ConfigTest.kt`, its Verify runs exactly that class,
and its first test intent is the opposite of the old assertion. The implementer sees the red test
in the same step and the fix is obvious.

### apps-5 (claimed minor)

**Claim.** On `com.android.settings`, buttons use `textAllCaps`, so the exact match against
"Force stop" fails and the run always ends in the toast.

**Refuter.** AC-26 targets the TV settings app; phone Settings is an extra fallback. The OK step
cannot break this way. Android 10 and later show "Force stop" in normal case. Even where it breaks,
the plan's safe exit (5 s, toast, nothing wrong pressed) applies. Refuted under "refute when
uncertain".

### delivery-5 (claimed minor)

**Claim.** `Config.save` always writes the same `config.json.tmp`, and three writers on different
threads use it, so overlapping saves can corrupt `config.json`.

**Refuter.** The writers cannot overlap in practice. Provisioner writes only right after a scripted
push. The drawer saves while Home is stopped. The column and drawer saves never run at once. Even an
overlap usually leaves complete JSON on Linux.

### delivery-6 (claimed minor)

**Claim.** The AC-31 host pin checks only the `url` string. `Fetcher.open` follows redirects, so a
redirect from tv.kevbox.dev to any https host still downloads.

**Refuter.** Not a gap against the spec. AC-31 pins the `url` field, and the pin's stated purpose
(catching a typo) holds. Only tv.kevbox.dev can redirect from tv.kevbox.dev, and whoever controls
that also controls `sha256`. Android's same-signature rule still blocks a foreign APK.

## Found during the fold, folded by the orchestrator

- **fold-1** (minor): `SystemLine`'s storage figure uses `Formatter.formatShortFileSize`, so unit names follow the system language and AC-38 leaks on a French TV. Noted on Task 3.
- **fold-2** (important, same root cause as apps-3): `HomeAccessibilityService.openCouch` started `MainActivity` by explicit component, which can create a second Home once KevBox Home is the real Home. Corrected in Task 10: it now calls `KevBox.goHome(this)`.
